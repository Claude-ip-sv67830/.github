<h2>一、四类场景的分水岭在哪</h2>
<p>分场景不看人数，看三个量和两个要求：并发峰值、单任务时长、号的数量，以及对稳定性的要求和预算上限。</p>
<h3>三个量加两个要求</h3>
<p>并发峰值决定要几条线；单任务时长决定会话保持要多久；号的数量决定池子要多大。这三个数不需要精确，量级对就够，比如「三到五个并发」「一次二十来分钟」「十来个号」。</p>
<p>另外两个要求决定预算：能不能接受偶发的中断，以及每月预算上限。能接受中断的，共享池加好环境隔离就够了；不能接受中断的，独享几乎是必选。</p>

<h2>二、单人两三个号：够用就好，别过度配置</h2>
<p>这是最容易被销售说服买多的场景。三个号配三条独享线，多数时候是浪费。</p>
<h3>配置与两个常见误区</h3>
<p>两条静态住宅线路加一套独立浏览器环境足够。号之间尽量分到不同 /24，其余交给环境隔离。真需要三条线，也是因为要同时在线，而不是因为「独享更安全」。</p>
<p>误区有两个。一是为了「更像真人」给每个号装一堆指纹插件，结果插件之间互相冲突，页面加载变慢还容易崩；三个号的规模，配置文件隔离加时区一致就够了。二是把独享当成必选项，两个号买两条线，钱花在了用不上的地方。</p>
<h3>试跑怎么做</h3>
<p>先买最短周期（常见 3 天或 7 天），把三个号都迁上去跑一遍完整流程：登录、连续对话、上传一份文档、跑一次长任务。三天内没有反复验证、没有掉线，就可以续。</p>

<h2>三、五到十号的小团队：一号一线，加共享台账</h2>
<p>这个规模是分水岭。再共用出口，撞段概率明显上升，管理也会开始混乱。</p>
<h3>配置与分工</h3>
<p>一号一条独享线，每人负责两到三个号，环境目录按「人-号-线」三级命名。台账用一个共享表格或数据库表，字段至少包含号、线路、环境目录、负责人、最近变更时间。</p>
<h3>试跑的重点是交接</h3>
<p>小团队的问题很少出在线路，多出在交接。试跑期就跑一次「换人接手」：让另一个人按台账接管一个号，看能不能在十分钟内跑通。跑不通说明台账或环境设计有问题，这时候改成本最低。</p>

<h2>四、内部系统批量开号：先搭网关，再谈线路</h2>
<p>机器跑的量和人跑的量不是一回事，配置要按并发来算，不是按号数来算。</p>
<h3>资源配比</h3>
<p>单出口跑一到两个会话，单机总并发不超过八到十个。五十个号同时在线，需要二十到三十条线，分布在两到三台机器上。这个配比不是理论值，是压测出来的经验区间。</p>
<h3>网关必须做三件事</h3>
<p>统一出口（业务只认本地一个端口）、健康检查（三十秒一次，连续两次失败切换）、限流（按号限速，防止单个任务把带宽吃满）。三件事缺一件，后面都会还债。</p>
<h3>试跑期别一次全量迁</h3>
<p>先迁 20% 的号，跑满十天，观察失败率和延迟分布。这期间保留旧线路跑剩下的 80%，出问题能立刻回退。全量迁移放在放量阶段，而不是试跑阶段。</p>

<h2>五、试跑流量和放量阈值</h2>
<p>「跑得挺好」不是放量依据，阈值才是。</p>
<h3>试跑流量怎么定</h3>
<p>按真实用量的 30%–50% 跑，不要只跑几百次请求就下结论。网页对话类单号三天大约消耗 300–600 MB，抓取类可能到 3–6 GB。流量太小看不出晚高峰的问题，太大又浪费试跑期。</p>
<h3>四条放量阈值</h3>
<p>连续五天满足：每百次请求验证次数低于 2 次、日均掉线低于 0.5 次、任务成功率高于 98%、P95 首字节低于 1.2 秒。四条同时满足才放量，缺一条就延长观察期。</p>
<h3>放量的节奏</h3>
<p>每次加 30% 的号，观察 48 小时。加号时同步扩备用容量，否则主线路一抖就接不住。三次加满即达到目标规模，整个过程约两周。</p>

<h2>常见问答</h2>
<h3>只有两个号，需要买独享吗？</h3>
<p>答：多数情况不需要。两个号用静态住宅或半独享，把环境隔开、出口不同段，稳定性已经够。独享的价值在号多、并发高、任务长的场景才体现出来。</p>
<h3>试跑期一定要满七天吗？</h3>
<p>答：看场景。单人号三天能看到主要问题；团队和批量场景建议七天以上，因为要覆盖一个完整的工作周，才能看到晚高峰和周末的差异。</p>
<h3>放量之后出问题，怎么快速回退？</h3>
<p>答：保留旧线路的凭证和环境目录至少一个月，别刚迁完就退订。回退时把号切回旧出口、恢复对应环境目录，通常半小时内能完成。</p>
<h3>小团队要不要专人管线路？</h3>
<p>答：五个号以内兼职管就行，靠台账。超过十个号，建议定一个负责人，每周花两小时做线路巡检和台账核对，比出问题后全员排查省时间。</p>
